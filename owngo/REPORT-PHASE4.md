## P4.2 Байти місця поза `main`

На виході процесу ті самі підсумки `FreeAccounted` (`os.Exit` → `ReportExit`): `owngo freed` і `owngo live` за категорією. Компілятор не змінювався. `FreeAccounted` для місця `static` поза `main` уже стоїть після P4.1.

Команди з кореня, LLVM 23 і LLD першими в `PATH`, `LLGO_ROOT=$PWD`. Обидві дали код 0.

`go run ./cmd/llgo run -tags owngo ./owngo/bytes/outstatic` — одне базове купове місце `[8]byte` у пакеті `site`, який не є `main`. Використання закінчується в `Static`, тож місце `static` і ці 8 байтів ідуть у `freed`. Живий `static` після виклику такий самий, як до нього:

```
owngo freed 144
owngo live static 984
owngo live rc-local 1736
owngo live rc-shared 368
owngo live pinned 2892
```

`go run ./cmd/llgo run -tags owngo ./owngo/bytes/outheld` — те саме місце `new([8]byte)` у пакеті поза `main`, передане в параметр `func`. Для v1 це `rc-local: shared`: `FreeAccounted` і `DecAccounted` немає, 8 байтів лишаються в `live rc-local`. `freed` і живий `static` не змінюються:

```
owngo freed 136
owngo live static 984
owngo live rc-local 1744
owngo live rc-shared 368
owngo live pinned 2892
```

Різниця між прогонами — 8 байтів: у першому вони в `freed` (144 − 136), у другому в `live rc-local` (1744 − 1736). Живий `static` в обох прогонах 984. Сама програма перевіряє цей приріст навколо місця і виходить з кодом 0 лише коли він дорівнює 8.

Поруч із заміром P2.3 і P2.4 лишаються 1 063 134 701 байт `static` двох рядків: 22.9% двох рядків і 14.5% профілю 17 сервісів. Звільнені фікстурою 8 байтів, і 144 байти всього процесу на першому прогоні, менші за половину того профілю (3 669 927 840). Цього кроку це досить. Профілі наново не знімались.
