## P6.3 Байти кільця

Вузол — `struct{ next *node; val int }`, 16 байтів користувача на amd64. Слово лічильника перед вузлом у підсумок не входить. Кільце двох вузлів — `a.next = b`, `b.next = a`; v1 позначає обидва місця рівно `cyclic`, прохід ставить `AllocCounted`, `Inc` на кожен запис у `next` і `DecCyclic` на останньому живому шляху кожного кореня.

Команди з кореня, Debian 13 amd64, `/usr/lib/llvm-23/bin` першим у `PATH`, `LLGO_ROOT=$PWD`. Обидві дали код 0.

`go run ./cmd/llgo run -tags owngo ./owngo/bytes/ring` — кільце звільняється після другого `DecCyclic`. 32 байти ідуть у `freed`, `live cyclic` після виклику такий самий, як до нього (0):

```
owngo freed 576
owngo live static 448
owngo live rc-local 1096
owngo live rc-shared 304
owngo live pinned 136
```

`go run ./cmd/llgo run -tags owngo ./owngo/bytes/ringheld` — те саме кільце, вузол `a` переданий у параметр `func(*node)`. Для v1 обидва вузли `cyclic: shared`: лічильника і `DecCyclic` немає, 32 байти лишаються в `live cyclic`:

```
owngo freed 544
owngo live static 448
owngo live rc-local 1096
owngo live rc-shared 304
owngo live cyclic 32
owngo live pinned 136
```

Різниця між прогонами — 32 байти, два вузли: у першому вони в `freed` (576 − 544), у другому в `live cyclic`. Решта рядків однакова. Сама програма перевіряє приріст навколо місця і виходить з кодом 0 лише коли він дорівнює `2 * unsafe.Sizeof(node{})`.

Поруч лишаються 1 528 993 142 байти `cyclic` приписаної купи (66.9% приписаної купи, 20.8% профілю). Звільнені фікстурою 32 байти, і 576 байтів усього процесу, менші за половину профілю (3 669 927 840). Цього кроку це досить.
