## P3.5 Байти, що пройшли через лічильник

На виході процесу ті самі підсумки `FreeAccounted` (`os.Exit` → `ReportExit`): `owngo freed` і `owngo live` за категорією. `DecAccounted` до нуля переносить розмір користувача в ці лічильники з категорією `rc-local`. Слово лічильника в розмір не входить.

Команди з кореня, LLVM 23 і LLD першими в `PATH`, `LLGO_ROOT=$PWD`. Обидві дали код 0.

`go run ./cmd/llgo run -tags owngo ./owngo/bytes/counted` — одне базове купове місце `[8]byte`, яке замикання тримає в тій самій горутині. Лічильник доходить до нуля на останньому читанні:

```
owngo freed 144
owngo live static 984
owngo live rc-local 1736
owngo live rc-shared 368
owngo live pinned 2892
```

`go run ./cmd/llgo run -tags owngo ./owngo/bytes/held` — те саме місце `new([8]byte)`, яке утримує невідомий виклик:

```
owngo freed 136
owngo live static 984
owngo live rc-local 1744
owngo live rc-shared 368
owngo live pinned 2892
```

Різниця між прогонами — 8 байтів: у першому вони в `freed` (144 − 136), у другому в `live rc-local` (1744 − 1736). Сама програма перевіряє цей приріст навколо місця і виходить з кодом 0 лише коли він дорівнює 8.

Поруч із заміром P2.3 і P2.4 лишаються 1 666 739 900 байтів `rc-local` двох рядків: 35.9% двох рядків і 22.7% профілю 17 сервісів. Звільнені фікстурою 8 байтів, і 144 байти всього процесу на першому прогоні, менші за половину того профілю (3 669 927 840). Цього кроку це досить. Профілі наново не знімались.
