# OwnGo — PLAN

Джерело правди — `INTENT.md`. Цей файл — задачі поточної фази з критеріями прийняття.
Детально розписана лише фаза 0; наступні фази деталізуються після її гейта.

## Правила роботи

1. **Одна задача — одна сесія.** Між задачами `/clear`.
2. **Explore → Plan → Code → Commit.** Код пишеться лише після узгодженого плану задачі.
3. **Тести раніше за реалізацію.** Спершу тести, переконатися, що падають, коміт; потім реалізація.
4. **Критерій прийняття перевіряється командою**, а не оцінкою «на око».
5. **Наприкінці сесії** — оновити `PROGRESS.md` і відмітити чекбокс тут.
6. **Рев'ю** — окрема сесія перевіряє зміни проти `INTENT.md`.

## Фаза 0 — Виміри

Мета: дізнатися, яку частку heap-алокацій реального коду покриває кожна стратегія каскаду, і чи потрібен трек M:N.

Інструмент — `census`: аналізатор `go/analysis` поверх `buildssa`, що класифікує кожне місце алокації.

| Категорія | Правило v0 |
| --- | --- |
| `stack` | `ssa.Alloc` з `Heap == false` |
| `static` | значення не зберігається в купу чи глобальну змінну, не захоплюється замиканням, не надсилається в канал, не повертається, не передається в `go` (лише всередині функції) |
| `rc-local` | решта, що не потрапляє в `rc-shared` |
| `rc-shared` | досяжне з `go`, надсилання в канал, глобальної змінної |
| `cyclic` | тип може досягти себе через поля-вказівники, слайси, мапи; інтерфейси — окремо, у двох режимах: строгий і консервативний |
| `pinned` | вказівник перетворюється в `unsafe.Pointer` |

Аргумент виклику в v0 вважається збереженням: таке місце не може бути `static`. Для кожного місця поза `stack` і `static` фіксується причина (аргумент виклику, замикання, канал, `go`, глобальна змінна, повернення, `unsafe`).

Місця алокації: `Alloc` (heap), `MakeSlice`, `MakeMap`, `MakeChan`, `MakeClosure` зі зв'язками, `MakeInterface` для не-вказівникових типів; неявні (`append`, конкатенація, перетворення рядків) — окремою категорією `implicit`.

## Передача вказівників (модель для v1)

Кожна передача вказівника отримує один із трьох станів:

| Стан | Умова | Операції |
| --- | --- | --- |
| Позичання | отримувач не зберігає вказівник | немає |
| Переміщення | отримувач зберігає, відправнику вказівник більше не потрібен (з урахуванням усіх аліасів) | немає |
| Спільне | обидва продовжують користуватися | `inc` при передачі, `dec` на останньому використанні; атомарні, якщо вказівник перетинає горутину (`go`, канал, глобальна змінна) |

Правила:

- «Невідомо» завжди трактується як «зберігає» і «потрібен»: ніколи не позичання.
- Зведення параметра: **позичає**, **споживає** або **невідомо**; обчислюється знизу вгору по графу викликів, для рекурсії — до нерухомої точки; stdlib — тим самим аналізом.
- Виклики через інтерфейс і `func`-значення — об'єднання зведень усіх цілей з графа викликів VTA; невідомий набір цілей — «невідомо».
- Внутрішні вказівники (`&s.f`, `a[:i]`) — той самий розбір, але лічильник ведеться для бази об'єкта.
- `append` звільняє старий масив лише якщо доведено відсутність інших зрізів; інакше масив спільний.
- Об'єкти цикличних типів у спільному стані реєструються як кандидати для збирача циклів.
- `unsafe.Pointer` → `uintptr` — закріплення, поза моделлю.

## Фаза 1 — доведений `free`

Гейт фази 0 не пройдено (P0.12). Задачі нижче стоять на трьох числах заміру юніт-тестів 17 сервісів (`owngo/REPORT-PHASE0.md`, ваги v1):

| Факт | Число |
| --- | --- |
| `static` + `rc-local` | 27.8% байтів приписаної купи: 636 572 452 з 2 286 316 727 |
| `static` після v1 | 12.1% тієї суми: 277 779 290 байтів |
| поза census | 67.6% байтів профілю: 4 963 968 984 |

Приписана купа — усі категорії, крім `stack`. Її суму тримає `cyclic` у `ms-export` (1 488 275 200 байтів, 65.1% приписаної купи). У `ms-faq` поза census — 98.8% байтів профілю. Профілі — юніт-тести, не prod.

Фаза звільняє лише місця, які v1 позначає `static`. `rc-local` входить у 27.8% і в цій фазі лишається живим до виходу процесу: лічильника ще немає. Те саме для `rc-shared`, `cyclic`, `implicit`, `pinned` і будь-якого місця, яке класифікатор не довів. Шлях алокатора — уже наявний `nogc`: `AllocU` через `malloc`, звільнення через `FreeRoot` → `c.Free` (`runtime/internal/runtime/z_nogc.go`). Другий алокатор фаза не додає.

Кожна задача приймається за своїм критерієм при будь-якій частці звільнених байтів, включно з часткою порядку `static`. Вимога «дешеві рівні покривають більшість купи» до фази 1 не застосовується. M:N у ці задачі не входить.
